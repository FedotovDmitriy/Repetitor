# Архитектура

## Общая схема

```
Браузер ──► Cloudflare Pages ── index.html            (всё приложение, один файл)
   │                          ── admin/index.html      (админ-панель)
   └──► /api/*  ──► Pages Function functions/api/[[route]].js
                         ├── D1 (база «DB»): семьи, дети, прогресс, обращения
                         ├── Google OAuth: вход по Gmail
                         └── Resend: письма
```

Приложение (`index.html`) — единый файл: стили, данные (темы, задачи, диагностики), схемы SVG и логика. Он не требует сборки. Сервер — один файл-обработчик, обслуживающий все адреса `/api/*`.

## Режимы хранения

При запуске приложение спрашивает `GET /api/me` и выбирает режим:

| Ответ `/api/me` | Режим | Где хранятся данные |
|---|---|---|
| не JSON / ошибка сети (нет сервера) | локальный | `localStorage` браузера (в claude.ai — общая база `window.claude`, если она есть) |
| JSON, `configured:true`, `google:false` | локальный + поддержка на сервере | как выше; сообщения поддержки уходят на сервер |
| JSON 401, `google:true` | облачный, не вошли | показывается страница входа |
| JSON 200 | облачный, вошли | документы семьи в D1 |

Приложение обращается к хранилищу через один и тот же интерфейс `db.doc(path).get/set/onSnapshot`; для облачного режима он реализован адаптером `makeCloudDb()` (опрос сервера раз в 8 секунд, только пока вкладка видима). Поэтому логика прогресса одинакова во всех режимах.

Ключи `localStorage`: `mvk-kids-v1` (дети), `mvk-active-v1` (активный ребёнок), `mvk-state-v1-<id>` (прогресс ребёнка), `mvk-parentpass-v1` (пароль родителя), `mvk-family-v1` (какой семье принадлежит кэш). При входе под другой семьёй или выходе кэш `mvk-*` очищается, чтобы данные не «перетекали» между семьями на общем компьютере.

## Данные в D1 (`db/schema.sql`)

- `families(id, owner_email, created_at, last_login)` — семья = родитель, вошедший через Gmail.
- `kid_emails(email, family_id)` — «Gmail ребёнка → семья»; обновляется при каждом сохранении списка детей.
- `docs(family_id, path, data, updated_at)` — документы семьи: `kids/list` (дети: `id, name, pin, grade, email`, а также `parentPass`) и `progress/<kidId>` (практика, тесты, диагностика, журнал).
- `support(id, created_at, family_id, email, kind, message, meta, status, emailed)` — обращения.
- `attempts(k, ts)` — счётчики для ограничения частоты.

## API

| Метод и адрес | Кто может | Что делает |
|---|---|---|
| `GET /api/me` | все | Кто я: `{ok,email,role,familyId}` или 401 с признаками настройки |
| `GET /api/auth/google` | все | Перенаправление на вход Google |
| `GET /api/auth/callback` | Google | Проверка входа, создание/поиск семьи, cookie сессии |
| `POST /api/auth/logout` | все | Удаляет cookie сессии |
| `GET/PUT /api/doc?path=…` | вошедшие | Чтение/запись документа семьи. Разрешены только `kids/list` и `progress/<id>`. Список детей меняет только родитель |
| `POST /api/support` | все | Сообщение в поддержку → запись + письмо администратору |
| `POST /api/pin-request` | родитель | Запрос PIN/пароля → запись + письмо администратору (при `AUTO_SEND_PINS=1` — сразу письмо родителю) |
| `POST /api/admin/login`, `/logout` | все / админ | Вход по мастер-паролю |
| `GET /api/admin/overview` | админ | Все семьи, дети, PIN, пароли, сводка прогресса |
| `GET/POST /api/admin/support` | админ | Список обращений; смена статуса |
| `POST /api/admin/send-pins` | админ | Письмо родителю с PIN-кодами и паролем кабинета |

## Кто входит и как

- **Родитель** входит через Google; его почта становится `owner_email` семьи (семья создаётся при первом входе). Роль `parent`.
- **Ребёнок** входит со своей почтой, если родитель вписал её в кабинете (`kid_emails`). Роль `kid`: видит страницу семьи и свой прогресс, не может добавлять детей, открывать кабинет родителя и запрашивать PIN.
- Дальше — значок ребёнка и PIN (проверяются в приложении), кабинет родителя закрыт паролем родителя.
- Если один и тот же адрес — владелец семьи и одновременно записан как «Gmail ребёнка», побеждает роль родителя.

Сессия — подписанный cookie `mvk_sid` (HMAC-SHA256, ключ `SESSION_SECRET`; `HttpOnly; Secure; SameSite=Lax`; 30 дней). Админ — отдельный cookie `mvk_adm` (12 часов).

## Безопасность и осознанные ограничения

- Google-токен получается сервером напрямую от Google по TLS; проверяются `aud`, `iss`, срок и `email_verified`. Параметр `state` защищает от подделки входа.
- Все пользовательские тексты в письмах и в админ-панели экранируются. Поле-ловушка (honeypot) и ограничение частоты защищают форму поддержки (5 сообщений в час на адрес), запрос PIN (3 в сутки на семью) и вход админа (8 попыток за 15 минут).
- Секреты хранятся только в переменных Cloudflare. В репозитории их нет.
- **PIN и пароль родителя хранятся открытым текстом** — это требование (администратор должен их видеть и отправлять). Поэтому PIN — «домашний замок» от случайного входа ребёнка в чужой профиль, а не защита банковского уровня. Не используйте в качестве пароля родителя пароли от важных сервисов.
- Проверка PIN и пароля родителя выполняется в браузере; вошедший ребёнок технически получает список детей вместе с PIN. Для домашнего использования это допустимо; при необходимости усиления — перенести проверку на сервер.
- Одновременное редактирование с двух устройств: последняя запись побеждает (документы целиком). Опрос раз в 8 секунд снижает риск, но не исключает его.

## Ограничения размеров

Один документ ≤ 400 КБ. Для семьи из нескольких детей это с большим запасом.

## Тесты

Серверная часть проверялась автоматически на локальной копии D1 (SQLite) с подставными ответами Google и Resend: вход родителя и ребёнка, права ролей, подпись cookie, запрос PIN, поддержка, ограничения частоты, админ-панель, отправка PIN. Приложение прогонялось в реальном браузере от страницы входа до выхода из аккаунта.
