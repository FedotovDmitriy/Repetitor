# Установка и подключение сервера

Сайт состоит из двух частей:

1. **Статическая часть** (`index.html`) — работает сразу после подключения репозитория к Cloudflare Pages.
2. **Сервер** (`functions/api/`, база D1, вход через Google, почта Resend) — нужен для входа через Gmail, общего прогресса на всех устройствах, писем поддержки и админ-панели. Подключается настройкой, код менять не нужно.

Сервер можно подключать по частям. Пока часть не настроена, сайт продолжает работать: см. таблицу «Что будет, если…» в конце.

> **Секреты** (пароль Google, ключ Resend, мастер-пароль) вводятся только в панели Cloudflare. Не вставляйте их в код, в GitHub и в чат.

## Шаг 1. Сайт на Cloudflare Pages

Проект уже подключён: репозиторий GitHub `FedotovDmitriy/Repetitor`, ветка `main`, адрес `repetitor-5oz.pages.dev`. Каждый `git push` в `main` запускает новую публикацию (1–2 минуты).

## Шаг 2. База данных D1

1. Cloudflare → **Workers & Pages → D1 SQL Database → Create database**. Имя: `mvk-db`.
2. Откройте базу → вкладка **Console** → вставьте всё содержимое файла `db/schema.sql` → **Execute**. Должны появиться таблицы `families`, `kid_emails`, `docs`, `support`, `attempts`.
3. Откройте проект Pages `repetitor` → **Settings → Bindings** (в старом интерфейсе: **Settings → Functions → D1 database bindings**) → **Add → D1 database**. Имя переменной **строго `DB`**, база `mvk-db`. Добавьте для Production и Preview.

## Шаг 3. Вход через Google

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) → создайте проект (например, «Математика в клетку»).
2. **APIs & Services → OAuth consent screen** → тип **External** → название приложения, ваша почта поддержки и почта разработчика → сохранить. Области (scopes) добавлять не нужно: используются только `openid` и `email`.
3. Там же нажмите **Publish app** (статус «In production»). Иначе войти смогут только «тестовые пользователи». Для таких простых областей проверка Google не требуется.
4. **Credentials → Create credentials → OAuth client ID** → тип **Web application**.
   - **Authorized redirect URIs:** `https://repetitor-5oz.pages.dev/api/auth/callback` (точно так, без пробелов и косой черты в конце).
5. Скопируйте **Client ID** и **Client secret** — они понадобятся на шаге 5.

## Шаг 4. Письма (Resend)

1. Зарегистрируйтесь на [resend.com](https://resend.com) **с почтой `fnemoy@gmail.com`**.
2. **API Keys → Create API Key** (право «Sending access») → скопируйте ключ (показывается один раз).
3. Ограничение бесплатного режима: отправитель по умолчанию `onboarding@resend.dev`, и Resend позволяет слать с него **только на почту владельца аккаунта**. Этого достаточно для писем поддержки вам. Для писем **родителям** (PIN-коды) нужен свой домен: добавьте его в Resend (**Domains**), пройдите проверку DNS и задайте переменную `MAIL_FROM`, например `Математика в клетку <support@ваш-домен.ru>`. Пока домена нет, PIN родителю можно переслать вручную из админ-панели (кнопка «Ответить» и таблица с PIN).

## Шаг 5. Переменные окружения

Pages → проект → **Settings → Variables and Secrets → Add** (для Production; для секретов выбирайте тип **Secret**):

| Переменная | Значение | Тип |
|---|---|---|
| `GOOGLE_CLIENT_ID` | Client ID из шага 3 | обычная |
| `GOOGLE_CLIENT_SECRET` | Client secret из шага 3 | секрет |
| `SESSION_SECRET` | длинная случайная строка, см. ниже | секрет |
| `ADMIN_PASSWORD` | ваш мастер-пароль для `/admin/` (12+ символов) | секрет |
| `RESEND_API_KEY` | ключ из шага 4 | секрет |
| `SUPPORT_TO` | `fnemoy@gmail.com` (можно не задавать — это значение по умолчанию) | обычная |
| `MAIL_FROM` | по желанию, только при своём домене в Resend | обычная |
| `AUTO_SEND_PINS` | `1` — запрос PIN сразу уходит письмом родителю (нужен домен); по умолчанию выключено | обычная |

Случайную строку для `SESSION_SECRET` можно получить в PowerShell:

```powershell
[guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
```

**После добавления привязки и переменных нужна новая публикация:** Pages → **Deployments → ⋯ у последней → Retry deployment** (или сделайте любой `git push`). Привязки и переменные применяются только к новым публикациям.

## Шаг 6. Проверка

1. Откройте `https://repetitor-5oz.pages.dev/api/me`. Ответ вида `{"ok":false,"configured":true,"google":true}` — сервер и база подключены. Если `"configured":false` — не создана привязка `DB` или не было новой публикации.
2. Откройте главную страницу: должна показаться страница со входом «Войти через Gmail». Войдите — откроется страница семьи.
3. Создайте ребёнка, откройте на другом устройстве (тот же Gmail) — ребёнок и прогресс должны совпасть.
4. Нажмите круглую кнопку поддержки, отправьте сообщение — письмо придёт на `fnemoy@gmail.com` и появится в `/admin/`.
5. Откройте `/admin/` и войдите мастер-паролем.

## Что будет, если часть не настроена

| Не настроено | Поведение |
|---|---|
| Ничего (сервера нет) | Сайт работает; прогресс — в браузере устройства; кнопка поддержки открывает почтовую программу с готовым письмом. |
| D1 есть, Google нет | Как выше, но кнопка поддержки отправляет сообщения на сервер (и в админку). |
| Google есть, Resend нет | Вход и синхронизация работают; обращения видны в `/admin/`, письма не приходят. |
| Нет `ADMIN_PASSWORD` | `/admin/` не пускает никого. |
| Нет своего домена в Resend | Письма поддержки вам приходят; письма родителям — нет (PIN пересылайте вручную). |

## Частые проблемы

- **«Вход отменён» / «Не получилось войти».** Проверьте, что в Google указан redirect URI **точно** `https://repetitor-5oz.pages.dev/api/auth/callback`, приложение опубликовано, а `GOOGLE_CLIENT_ID`/`SECRET` не перепутаны.
- **После входа снова страница входа.** В браузере отключены cookies для сайта, либо не задан `SESSION_SECRET`.
- **Письма не приходят.** Проверьте `RESEND_API_KEY`; в админке у обращения будет пометка «письмо не ушло»; загляните в спам; помните про ограничение `onboarding@resend.dev`.
- **Родитель потерял доступ к Gmail.** Перенести семью на другую почту можно вручную в базе D1: `UPDATE families SET owner_email='новая@почта' WHERE owner_email='старая@почта';`.
- **Свой домен вместо `repetitor-5oz.pages.dev`.** Pages → Custom domains. После смены адреса обновите redirect URI в Google.
